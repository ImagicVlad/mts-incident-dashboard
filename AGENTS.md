# Рабочие правила

Перед изменениями прочитать PROJECT_SPEC.md и docs/DATA_CONTRACT.md. Сохранять композицию исходного Svelte-прототипа, использовать React/TypeScript и FastAPI. Источник инцидентов — массив в серверном JSON. Новая бизнес-логика классификации принадлежит backend. Перед коммитом выполнить проверки из README. После каждого запроса с изменениями создать отдельный коммит и отправить его в текущую ветку, когда для проекта настроен origin и разрешена публикация. Хранить исходные файлы ментора и .env только локально.
