# Контракт данных

Источник — массив из character_problems.json. Справочник incidents_attributes.json содержит 30 описаний полей, это отдельный набор. Проверенная выгрузка содержит 44 записи с 46 полями. Публичное демо воспроизводит структуру на вымышленных значениях.

DTO сохраняет строковые идентификаторы, основные исходные названия и null. Статус определяется известным stateEnum, резервная таблица кодов построена по фактическим записям: 0 Assigned, 2 WorkInProgress, 7 Resolved, 10 Closed, 20 Research. У справочника 7 и 10 расходятся с выгрузкой, 20 отсутствует. В исходных данных статусы встречаются 14, 10, 10, 5 и 5 раз соответственно. У всех Research есть completionDate. Наличие solution или completionDate само по себе не завершает инцидент. waitingExitDate с годом 0001 трактуется как отсутствие значения. isNeedUp допускает три состояния. Тип непустого productUrl выгрузкой не подтверждён. По справочнику isEffect обозначает причину, isReason — дочерний инцидент. Построение дерева имеющимися полями не предусмотрено.

Сверка групп на исходном файле на 21 ноября 2026 года в 00:00 МСК даёт critical 1, assigned 2, high 0, review 5, history 15. Единственная активная запись с высоким приоритетом к этому моменту просрочена и учитывается в critical. Сервер определяет срочность по своим часам и публикует новую версию снимка также при достижении порога срочности. Поле dataUpdatedAt показывает время обновления данных из файла. Даты хранятся в UTC, интерфейс показывает московское время.

## Поля карточки

| Исходное поле | Назначение |
| --- | --- |
| id, sysId | Номер инцидента и внутренний ключ. Уникальные непустые значения хранятся строками. |
| header, productName, service | Заголовок, продукт и сервис. |
| description, shortDescription | Полное и краткое описание. |
| assignedGroupName, assignedEmployee | Ответственная команда и назначенный сотрудник. |
| submitDate, deadline, completionDate | Возникновение, срок и завершение по данным источника. |
| stateEnum, state, stateId | Стадия, подпись и исходный код. |
| priorityId, priority | Код и подпись приоритета. |
| solution | Текст решения в источнике; при открытом статусе тоже может быть заполнен. |

Пропущенные даты и поля остаются пустыми. Длинные идентификаторы сохраняют точность. Дополнительные поля допускаются. Неизвестное перечисление или несогласованность исходных полей сопровождается диагностикой. В каждой очереди записи упорядочены по убыванию приоритета от 4 до 1, неизвестный приоритет идёт последним. У координаторов критические образуют первую группу. При равном приоритете очереди срочности показывают ближайшие сроки, координаторы — самые давние назначения по lastAssignmentToTeamDateTime, исследование и история — последние устранённые сбои по completionDate. При сравнении дат отсутствующие значения идут последними, равные даты упорядочиваются по номеру записи.

## Данные смены для защиты

Рабочий JSON — полный массив исходных объектов. При сборке смены в него копируются все поля записей ментора, включая неизвестные модели API. Сценарные записи повторяют структуру выгрузки и имеют дополнительный атрибут `dataOrigin` со значением `defense-scenario`. Номера инцидентов и длинные внутренние ключи передаются строками. Справочник атрибутов хранится отдельно.

У исходных записей ментора сохраняются абсолютные даты. Даты сценарной части в шаблоне привязаны к 5 января 2026 года, 09:00 UTC. При старте все они сдвигаются на одну величину. В расписании `afterSeconds` задаёт время от начала смены, `id` и `changes` обновляют конкретную запись, а `new` вводит полную новую запись. Подготовленное событие публикуется атомарной заменой рабочего массива. Существующий поток SSE доставляет снимок с новыми карточками и счётчиками.

## HTTP и события

| Метод и путь | Тело / ответ |
| --- | --- |
| POST /api/auth/login | Принимает login и password. Возвращает профиль и устанавливает HttpOnly cookie. |
| GET /api/auth/me | Профиль текущей сессии с login и displayName. |
| POST /api/auth/logout | Отзывает сессию; ответ 204. |
| GET /api/health | Доступность HTTP, флаг aiConfigured и displayTimezone. |
| GET /api/incidents | Полный снимок с incidents, groups, counts, notifications и диагностикой. |
| GET /api/incidents/events | Поток text/event-stream; именованное событие snapshot передаёт полный снимок. |
| GET /api/incidents/{id} | Карточка указанной записи. |
| POST /api/ai/summary | Принимает incidentId. |
| POST /api/ai/chat | Принимает messages из пар role/content; до 9 сообщений и 2000 символов в вопросе. |

Для данных и ИИ нужна сессия. В ответе ИИ присутствуют answer, asOf, epoch, snapshotVersion и признак stale. Ошибки возвращают detail. Схемы запросов и ответов доступны в /openapi.json и /docs на FastAPI.

Каждый счётчик равен длине соответствующего списка в groups. Списки critical и high взаимоисключающие. Принадлежность к assigned определяется статусом и точным именем команды «КЦ ИТ Координаторы Массовых Инцидентов». Метаданные loadedAt, dataUpdatedAt и serverTime принадлежат приложению. epoch меняется при перезапуске, snapshotVersion возрастает при изменении публикуемого состояния, включая ошибку источника и восстановление. Доступность файла описывают sourceStatus, sourceError и hasSnapshot. Новая подписка начинает с текущего полного снимка и последних событий. По eventId интерфейс различает события и подавляет повторные уведомления при восстановлении связи.
