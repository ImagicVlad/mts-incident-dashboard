# Пульт координатора инцидентов

Веб-приложение для дежурной смены. FastAPI читает исходный JSON с инцидентами и публикует изменения через SSE. React показывает очереди, поиск, назначение и ближайший срок. При разборе инцидента координатор может запросить ИИ-сводку или задать вопрос по смене.

## Быстрый старт с Docker

Из корня репозитория выполните:

```sh
docker compose up --build -d --wait
```

Откройте [пульт](http://localhost:8080). Демонстрационный логин — `coordinator.demo`, пароль — `mts-demo-local`. При первом запуске без настроек используются десять синтетических записей с датами относительно времени запуска. Для остановки выполните `docker compose down`. Требуется Docker Compose с поддержкой необязательного env-файла (v2.24+).

## Локальная разработка

Проверенная среда — Node.js 24, Python 3.14 и uv. Из корня репозитория запустите API:

```sh
cd backend
uv sync --frozen
uv run --frozen uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В отдельном терминале из корня запустите интерфейс:

```sh
cd frontend
npm ci
npm run dev
```

Откройте [интерфейс разработки](http://localhost:5174). Vite проксирует `/api` на порт 8000. Оба варианта запуска используют cookie одного origin. [Интерактивный OpenAPI](http://127.0.0.1:8000/docs) доступен в режиме разработки.

## Подключение своей выгрузки

1. Создайте каталог `data/local` в корне. Поместите в него `character_problems.json`. Файл `incidents_attributes.json` можно положить рядом для сверки справочника.
2. Скопируйте `backend/.env.example` в `backend/.env`. Для существующей установки отредактируйте текущий файл.
3. Задайте `INCIDENTS_FILE=../data/local/character_problems.json` и перезапустите backend. В Compose выполните `docker compose up -d --force-recreate backend web`.

Относительные пути считаются от каталога `backend`. Для локального запуска также поддерживается абсолютный путь. В Compose доступен примонтированный каталог `/app/data/local`. Во время работы сохраняйте новую версию массива по тому же пути — изменения станут видны в списках и в открытой карточке. Ошибки выбранного файла видны на дашборде. Для сетевых дисков доступен `WATCH_POLLING=true`. Файлы ментора и настройки исключены из Git и Docker-контекста.

## Смена для защиты

Рабочий массив находится в `data/local/defense/character_problems.json`. Смена начинается с исходной выгрузки ментора из `data/local/character_problems.json` и подготовленных обращений из `data/defense/shift.json`. У подготовленных записей есть поле `dataOrigin: "defense-scenario"`. В интерфейсе их источник виден в карточке. Расписание изменений для этих записей хранится в `data/defense/timeline.json`.

1. Для первого запуска подготовьте окружение backend по инструкции выше. Из корня репозитория выполните `backend\.venv\Scripts\python.exe scripts/defense_shift.py prepare`. Команда создаст начальный рабочий файл. На Linux используйте `backend/.venv/bin/python`.
2. Укажите в `backend/.env` значение `INCIDENTS_FILE=../data/local/defense/character_problems.json` и запустите или перезапустите API. Откройте дашборд.
3. В момент начала показа откройте `run-defense.cmd` из корня проекта или выполните `backend\.venv\Scripts\python.exe scripts/defense_shift.py run`. Начнётся новая смена. Сроки подготовленных обращений отсчитываются от старта, даты выгрузки ментора сохраняются. Можно держать рядом открытыми очередь и карточку одного инцидента.

С предоставленной выгрузкой при старте в пульте 64 записи, из них 20 подготовлены для этой смены. Время в таблице отсчитывается от запуска `run`.

| Время | Что показать на дашборде |
| --- | --- |
| 0:20 | Поступает 65-е обращение INC-900006 о публикации записи вебинара. Координаторам приходит оповещение. |
| 0:45 | INC-900001 о задержке платежей переходит из «Высокого приоритета» в «Критические» по часам сервера. |
| 1:10 и 1:55 | Координаторы передают профильным командам активный сбой мобильного интернета и разбор ранее устранённого сбоя голосовой связи. |
| 2:40 | Отложенные платежи зачислены. INC-900001 переходит в «Исследование». |
| 3:25 и 4:20 | Команда видеоплатформы берёт INC-900006 в работу. У мобильного интернета подтверждено восстановление. |
| 5:15 и 6:05 | Обращение по вебинару переходит в историю, затем ранее решённый инцидент по роумингу закрывается. |

После последнего события рабочий файл сохраняет итог смены. Повторный запуск сценария заново формирует его из двух исходных наборов. Чтобы воспроизвести только публичную часть на другом компьютере, добавьте `--scenario-only` и к подготовке, и к запуску. Для подключения выгрузки из своей ITSM используйте инструкцию выше.

## Работа в пульте

- Нажмите на верхний счётчик, чтобы открыть очередь. Подчёркнутый заголовок переключает её между первыми двумя карточками и полным списком.
- Поиск включает все записи, в том числе открытые инциденты за пределами четырёх групп. Номер открывает карточку на `/incidents/:id`.
- Колокольчик показывает события возникновения критического инцидента, его устранения и назначения координаторам. Первая загрузка задаёт исходное состояние.
- Стадия исследования остаётся отдельной очередью. На карточке видны исходные даты и назначение. Завершённые и закрытые записи попадают в историю.
- Изменения команды, статуса и срока вносятся во внешний источник. Для ссылки на него задайте, например, `ITSM_URL_TEMPLATE=https://itsm.example.org/incidents/{sysId}`. Вместо `{sysId}` можно использовать `{id}`.

## ИИ и настройки входа

Для чата и сводок укажите ключ OpenAI в `LLM_API_KEY` в локальном файле `backend/.env` и перезапустите backend. По умолчанию сервер обращается к `gpt-5.4-mini` через `https://api.openai.com/v1`. Модель и адрес можно изменить через `LLM_MODEL` и `LLM_BASE_URL` для совместимого с Chat Completions провайдера. Ключ остаётся на сервере. При отправке вопроса или запросе сводки провайдер получает релевантные поля инцидентов. Для чата также передаётся ограниченная история переписки. Лимит генерации составляет 700 токенов на ответ. Сводка содержит версию снимка. Если за время ответа данные изменились, интерфейс отмечает это. Без ключа поиск, сроки, оповещения и обновления продолжают работать.

Учётная запись задаётся через `DEMO_LOGIN`, `DEMO_PASSWORD` или готовый Argon2-хеш в `DEMO_PASSWORD_HASH`. Публичные демореквизиты предназначены для локальной демонстрации. Для HTTPS включите `COOKIE_SECURE=true` и укажите адрес интерфейса в `ALLOWED_ORIGINS`. Срок сессии задаётся `SESSION_TTL_SECONDS`. Настройка часового пояса — `DISPLAY_TIMEZONE`, изначально `Europe/Moscow`.

## Пошаговая демонстрация

Из корня выполните `python scripts/demo.py init`. Укажите `INCIDENTS_FILE=../data/runtime/scenario.json` и перезапустите backend. Откройте дашборд в двух вкладках. Команда `python scripts/demo.py walk` инициализирует **только демонстрационную копию** и ждёт Enter перед каждым шагом.

| Шаг | Что видно в интерфейсе |
| --- | --- |
| add | Появляется критический DEMO-LIVE-01 |
| assign | Запись одновременно видна в критических и у координаторов |
| deadline | В карточке меняется срок |
| resolve | Запись переходит в историю, в ленте остаётся сообщение об устранении |
| research | Запись перемещается в исследование и появляется у координаторов |
| break | Показана ошибка чтения, последняя корректная выгрузка остаётся на экране |
| restore | Ошибка исчезает, данные снова актуальны |

Каждый шаг можно запустить отдельно, например `python scripts/demo.py add`. Для воспроизводимой даты передайте `--at 2026-11-21T10:00:00+03:00`. Обычный деморежим без `INCIDENTS_FILE` формирует файл `data/runtime/preview.json` при каждом старте.

## Проверки

```sh
cd backend
uv run --frozen pytest -q
cd ../frontend
npm ci
npm run build
npx playwright install chromium
npm test
```

Playwright запускает отдельные серверы на 8016 и 5186 и меняет собственную синтетическую копию JSON. Для установленного Chrome можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. После запуска контейнеров выполните `python scripts/smoke.py` для проверки маршрута SPA, cookie, получения снимка и SSE через Nginx. Для dev-сервера передайте `http://127.0.0.1:5174` как аргумент. CI повторяет сборку, тесты и запуск Compose.

Один процесс backend обслуживает все соединения. При перезапуске сессии и последние 100 событий очищаются, текущие записи загружаются из файла. Структура API и допущения описаны в [контракте](docs/DATA_CONTRACT.md), функции продукта — в [спецификации](PROJECT_SPEC.md).
